## 1. 架构概览

### 1.1 整体架构

```
前端 (Vue 3 + Naive UI)
  /admin/media                 Tab: 视频 ── VideoList + UploadTaskPanel(侧边)
  (统一媒体管理)               Tab: 文件 ── FileList + FileUploadModal

  LargeFileUploader            分片上传客户端（MD5/秒传/断点续传）
  useUploadWithDraft           上传状态机 + 草稿续传

            ▼ HTTP REST

后端 (Spring Boot 3)
  AdminVideoApi    AdminVideoBatchApi    AdminVideoCategoryApi
  AdminVideoStatsApi    FileApi    LargeFileUploadApi

  VideoService    FileService    LargeFileUploadService
  VideoTranscodingService (FFmpeg HLS)

  PostgreSQL: file_metadata + file_upload_task + file_chunk + video_category
  Redis:      仅 MD5 映射缓存（TTL 24h）
```

### 1.2 设计原则

| 原则 | 说明 |
| :--- | :--- |
| **一张表** | `file_metadata` 承载所有媒体（`fileType` 区分），不建独立视频表 |
| **DB 主存储** | 上传任务存 `file_upload_task` 表，Redis 仅 MD5 缓存 |
| **一步完成** | `completeUpload(businessId, uploadId)` 事务内 合并+更新+转码 |
| **前端统一** | `/admin/media` Tab 切换，侧边面板管上传任务 |

## 2. 数据模型

### 2.1 file_metadata（文件/视频统一表）

| 字段分组 | 字段 | 说明 |
|:---|:---|:---|
| 存储 | url, path, filename, originalFilename, fileExt, fileSize, contentType, platform, basePath | x-file-storage 映射 |
| 分类 | fileType, categoryId, categoryName, description, isPublic | fileType ∈ {video, image, document, archive, other} |
| 哈希 | hashInfo, objectId, objectType | |
| JSON | metadata, userMetadata, attr | |
| **视频** | title, slug, coverUrl, hlsUrl, sourceUrl, duration, width, height, fileFormat, videoType, tags | fileType='video' 时有效 |
| **统计** | viewCount, likeCount, coinCount, favoriteCount | |
| **状态** | videoStatus, publishedAt, sortWeight | 见 2.2 |
| **转码** | originFileId, transcodingProgress, errorMessage | |

```sql
CREATE TABLE file_metadata (
    id BIGINT PRIMARY KEY,
    url VARCHAR(1000), path VARCHAR(500),
    filename VARCHAR(500), original_filename VARCHAR(500),
    file_ext VARCHAR(20), file_size BIGINT,
    content_type VARCHAR(100), platform VARCHAR(50), base_path VARCHAR(500),
    file_type VARCHAR(20) NOT NULL,
    category_id BIGINT, category_name VARCHAR(100),
    description TEXT, is_public BOOLEAN DEFAULT false,
    hash_info TEXT, object_id VARCHAR(100), object_type VARCHAR(50),
    metadata TEXT, user_metadata TEXT, attr TEXT,
    title VARCHAR(255), slug VARCHAR(255),
    cover_url VARCHAR(500), hls_url VARCHAR(500), source_url VARCHAR(500),
    duration INT, width INT, height INT, file_format VARCHAR(20),
    video_type VARCHAR(20), tags VARCHAR(500),
    view_count INT DEFAULT 0, like_count INT DEFAULT 0,
    coin_count INT DEFAULT 0, favorite_count INT DEFAULT 0,
    video_status VARCHAR(20), published_at TIMESTAMP,
    sort_weight INT DEFAULT 0, origin_file_id BIGINT,
    transcoding_progress INT, error_message TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 2.2 VideoStatus 状态机

```
DRAFT ──(上传完成)──▶ PROCESSING ──(提交)──▶ TRANSCODE ──(成功)──▶ COMPLETED ──(发布)──▶ PUBLISHED
  │                      │                      │                      │                    │
  └──────────────────────┴──────────────────────┴──────────────────────┴──(失败)──────────▶ FAILED (可重试)
```

### 2.3 file_upload_task（上传任务表，替代 Redis Hash）

```sql
CREATE TABLE file_upload_task (
    id BIGINT PRIMARY KEY,
    upload_id VARCHAR(64) NOT NULL UNIQUE,     -- UUID，前端持有
    business_id BIGINT,                        -- FK → file_metadata.id
    file_name VARCHAR(500) NOT NULL,
    file_size BIGINT NOT NULL,
    file_md5 VARCHAR(64) NOT NULL DEFAULT '',
    chunk_size BIGINT DEFAULT 5242880,         -- 5MB
    total_chunks INT NOT NULL,
    uploaded_chunks INT DEFAULT 0,
    status VARCHAR(20) DEFAULT 'INIT',         -- INIT/UPLOADING/MERGING/COMPLETED/CANCELLED/FAILED
    platform VARCHAR(50),
    file_info_json TEXT,                       -- x-file-storage FileInfo 序列化
    error_message VARCHAR(1000),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_task_md5_status ON file_upload_task(file_md5, status);
CREATE INDEX idx_task_business ON file_upload_task(business_id);
```

**Redis 定位**：仅缓存 `file:upload:md5_map:{md5} → uploadId`（TTL 24h），用于秒传/断点续传快速查。

### 2.4 file_chunk（分片记录，幂等保护）

```sql
CREATE TABLE file_chunk (
    id BIGINT PRIMARY KEY,
    upload_id VARCHAR(64) NOT NULL,
    filename VARCHAR(500), file_size BIGINT,
    chunk_number INT NOT NULL, chunk_size BIGINT,
    total_chunks INT, chunk_md5 VARCHAR(64),
    status VARCHAR(20) DEFAULT 'uploading',
    path VARCHAR(500), user_id BIGINT,
    completed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX uk_file_chunk_number ON file_chunk(upload_id, chunk_number);
```

### 2.5 video_category

```sql
CREATE TABLE video_category (
    id BIGINT PRIMARY KEY, name VARCHAR(50) NOT NULL,
    code VARCHAR(50) NOT NULL UNIQUE, description VARCHAR(255),
    icon VARCHAR(50), sort_order INT DEFAULT 0, parent_id BIGINT,
    created_at TIMESTAMP, updated_at TIMESTAMP
);
```

## 3. 大文件分片上传

### 3.1 完整流程

```
点击上传文件 打开上传对话框（除了从任务管理器恢复调整，其他情况都需要重新初始化），选择大文件上传，选取文件，点击开始上传 
1 -> 初始化（文件分片以及md5计算） 
 - 这时候允许点击取消按钮取消上传
 - 这时候关闭窗口，先提示（取消上传还是后台上传），取消上传确定后如果没有完成初始化直接前端取消上传，如果已经完成初始化还需要调后台取消上传
2 -> 上传分片 
 - 这时候运行点击暂停按钮暂停上传。暂停后点击继续上传继续分片上传
 - 这时候关闭窗口，先提示（取消上传还是后台上传），后台上传的，之后只能从上传任务管理器中暂停
 - 关闭窗口后台上传的，分片全部上传后需异步完成合并请求
3 -> 合并分片完成上传
```

### 3.2 LargeFileUploader 客户端配置

| 项 | 值 |
|:---|:---|
| chunkSize | 2MB |
| parallelUploads | 3 |
| retryChunks | 3 |
| verifyChunks | true |

### 3.3 useUploadWithDraft 状态机

```
IDLE → COMPUTING_MD5 → UPLOADING → MERGING → SUCCESS
  │         │              │           │
  └─────────┴──────────────┴───────────┴──→ ERROR ──(重试)──→ UPLOADING
```

草稿续传：`setBusinessId(draftId)` → `startUpload(file)` 跳过创建草稿。

## 4. 视频转码

```
VideoTranscodingService.submitTranscodeTask(videoId, filePath) [@Async]
  1. downloadToTempFile()    本地 / x-file-storage download / HTTP URL
  2. getVideoInfo(ffprobe)   → duration, width, height
  3. transcodeToHLS(ffmpeg)  → index.m3u8 + segment_*.ts
  4. uploadHLSToStorage()    → x-file-storage
  5. updateAfterTranscode()  → status=COMPLETED, hlsUrl, duration, w/h

失败 → status=FAILED
重试 → retryTranscode(id) → submitTranscodeTask(id, video.url())
```

## 6. 前端组件设计

### 6.1 目录结构

```
src/views/admin/media/
└── index.vue                     # 统一媒体管理（Tab 切换）

src/views/admin/videos/components/
├── VideoList.vue                 # 视频列表（卡片+表格，默认 COMPLETED+PUBLISHED）
├── VideoForm.vue                 # 上传/编辑表单（resumeDraftId prop）
├── UploadTaskPanel.vue           # 侧边面板（可折叠）
└── VideoStatsModal.vue           # 统计

src/views/admin/files/components/
├── FileList.vue                  # 文件列表
└── FileUploadModal.vue           # 上传弹窗（简单 + 分片 Tab）

src/composables/
├── useUploadWithDraft.ts         # 上传状态机 + 草稿续传
├── useViewMode.ts                # 卡片/表格切换
└── useBatchOperation.ts          # 批量操作

src/api/
└── files.ts                      # 文件 API + LargeFileUploader
```

### 6.2 UploadTaskPanel

| 状态 | 标签 | 操作 |
|:---|:---|:---|
| DRAFT | default "草稿" | 上传 / 删除 |
| PROCESSING | warning "处理中" + 进度条 | 删除 |
| TRANSCODE | warning "转码中" + 脉冲指示 | 删除 |
| FAILED | error "失败" | 重试 / 删除 |

- 10s 自动刷新；有活动任务时黄色脉冲灯
- 数据源：`GET /api/admin/videos/tasks`
